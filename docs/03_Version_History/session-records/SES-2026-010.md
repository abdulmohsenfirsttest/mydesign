## 2. Versions shipped

**v4.7.0 · Testing-feedback UX: session-aware navbar + one-step milestone deliverable**
- What: (1) **Session-aware navbar** — `app/components/Navbar.tsx` always showed "Client Login" and read no session, so returning logged-in users re-authenticated. It now shows **"My Dashboard"** (client) / **"Admin Panel"** (staff) when a `localStorage` session exists, and `app/auth/login/page.tsx` **redirects an already-logged-in visitor** to their portal instead of showing the form. (2) **One-step milestone deliverable** — the New Milestone form (`app/admin/messages/page.tsx`) gained an optional **Deliverable** file field so a milestone can be created **Completed in one save**; the Status dropdown **greys out "Completed" with inline guidance** until a file is attached (replacing the post-submit red error), and clearing the file steps a Completed selection back to In Progress. Existing per-milestone attach-then-complete flow unchanged.
- Why: testers reported having to "log in again when we return to the main page" (the session was never lost — a navbar affordance gap) and hit the milestone "can't start as Completed" wall when posting a finished moodboard.
- Schema: none — deliverable writes to the existing `milestones.files` jsonb (migration 0002); navbar reads the existing `localStorage` session.
- Decision: MINOR. The re-login complaint is fixed as **UX, not auth** — the localStorage model is unchanged (client-side enforcement; Security Phase 2 still pending, ADR-0010). Milestone form now supports create-and-complete-in-one-step while keeping the deliverable-before-Completed rule, enforced *before* submit.

## 3. Schema changes

None. v4.7.0 is app-code only (a jsonb write to an existing column; a client-only session read).

## 4. Architectural decisions

- **The "re-login" report is an affordance bug, not a session bug** — verified the localStorage session persists across navigation; the fix is to surface a portal link + skip the login form when already authenticated, not to touch the auth model. (Stays under ADR-0001/0002; real session/expiry is Security Phase 2.)
- **Admin takes precedence in the navbar** when both `admin_session` and `client_id` are present in localStorage (edge case). Chosen deliberately; revisit if a staff member also needs a one-click client view.
- **The deliverable-before-Completed rule is preserved, moved earlier** — instead of rejecting a Completed submit, the UI prevents selecting Completed until a file is attached. Same invariant (a Completed milestone always has ≥1 deliverable), better ergonomics.
