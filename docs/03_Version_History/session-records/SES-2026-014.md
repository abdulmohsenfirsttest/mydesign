**v4.9.2 · Fix: a project's stage and progress could never change (BUG-017)**
- **What:** A designer filmed production showing Balconia Tower Apartment with a **Completed** milestone (20.8 MB deliverable attached), an **In Progress** one and a **Skipped** one — while the hub header, the Projects list, the Admin Dashboard and the client's portal all still read **`Quotation` / `0%`**. Cause: `projects.stage`/`progress` are written in only two places — project creation (`app/admin/projects/page.tsx:76`, always `Quotation`/0) and the client approving a proposal (`app/dashboard/projects/[id]/page.tsx:126`, always `Mood Board`/28). `updateStage()` at `app/admin/messages/page.tsx:740` — the one function that walks a project through the seven stages — was fully written and **had zero callers**; v4.3.0 removed its dropdown and left the function, its `stageProgress` map and its `updatingStage` flag as dead code for six weeks. Milestones never touch `projects`, and there is **no DB trigger** in any of the nine migrations. So staff could complete every milestone and nothing would move, and no manual control existed either. Fixed by making the header stage badge a `<select>` over the seven stages wired to the existing `updateStage()`, which now also **reads its Supabase error** instead of updating local state unconditionally.
- **Why:** designer report, 2026-08-16, on production with real client projects.
- **Schema:** none. No migration.
- **Decision:** PATCH — restores a control removed by accident; no new capability. Deliberately **did not** auto-derive stage from milestones: designers name milestones freely ("quotation", "Balconia Tower TownHouse 3D Design"), so they don't map onto the seven fixed stages. Deriving the **percentage** from completed-vs-total is the tractable half and is left as a follow-up in BUG-017.

## 4. Architectural decisions

- **Removing a UI control must remove its handler.** `updateStage()` survived v4.3.0 as an orphan and read, to anyone opening the file, as a working feature. Lint does not flag an unreferenced *function declaration* the way it flags an unused variable, so nothing caught it for six weeks. When a control is deleted, delete its handler or leave a comment saying why it stays.
- **Never `await` a Supabase write without reading `error`.** `updateStage()` had the same shape that caused BUG-010: write, ignore the result, update local state anyway — which renders success on screen for a write that did not happen. Every mutation in this codebase should destructure `{ error }` and return early.
- **Stage and progress are different concepts and should stop sharing a source.** Stage is a position in a fixed seven-step pipeline and belongs to staff judgement. Progress is a percentage and should be computable from the milestone plan. Coupling them through one `stageProgress` lookup is why "0% complete" was meaningless.

Combined with the anon key in every browser bundle and RLS off on 11 of 12 tables, working owner credentials are publicly readable.
