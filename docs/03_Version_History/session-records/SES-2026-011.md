## 1. Summary

Follow-up to the team's second testing report, which claimed two failures: "light and dark modes not functioning" and "still unable to upload files." Investigation showed **neither was an app regression**: light/dark had never been deployed (it was deferred to its own branch — an expectation gap), and the upload path was proven healthy end-to-end with live probes, with **zero upload requests having reached Supabase since 2026-07-13** — the reported failures never left the testers' browsers (stale tabs/cached pre-fix JS suspected). The probing surfaced a real adjacent bug — **storage buckets had no DELETE policy**, so file-deletes silently orphaned objects — fixed as **v4.7.1**. The light/dark theme was then actually built on `feature/light-dark`, owner-reviewed on a Vercel branch preview (shareable link), and merged as **v4.8.0**.

## 4. Architectural decisions

- **Diagnose before believing a bug report.** Both reported "regressions" were disproven with live evidence (served-JS grep, anon API probes, server-side request absence) before touching code. Recorded in BUG-010 (related-finding note) and BUG-012.
- **Theme = semantic tokens, not class toggling.** All theming flows through CSS variables flipped by one `data-theme` attribute; components reference only semantic utilities. Photographic surfaces are exempt by design.
- **Tailwind v4 gotcha locked in:** utilities like `border-soft` resolve via `--color-soft` — compound token names need explicit aliases in `@theme` or the class silently emits no CSS. Caught in verification; the aliases live in `globals.css`.
- **Vercel Preview environment is now a real environment for this project** (first preview deploy ever): `NEXT_PUBLIC_SUPABASE_*` added to Preview (branch-scoped). Preview deployments sit behind Vercel SSO; team access requires a shareable link.
