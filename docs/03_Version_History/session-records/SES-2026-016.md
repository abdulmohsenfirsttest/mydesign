## 1. Summary

The owner asked for the front end of his Wix site, mydesign.sa, to be cloned into this app as real pages: its images, videos and style, but **not** the domain. He set three rules: never change anything on Wix, skip the privacy/accessibility pages, and move the domain last, only on his word.

The rebuild was done on 2026-09-27/28 in a separate worktree (`~/mydesign-v5`, branch `feature/v5-wix-clone`), previewed in Arc on port 3200, and then sat uncommitted awaiting approval. On 2026-09-30 he reviewed the homepage and said **"deploy all the new homepage"**. That was taken as approval of the whole v5 public site (home, `/projects`, `/book`) for production. The domain move and the unshipped firewall work were not part of it.

The same session opened with a full read-only recall sweep of the project (repo, live DB, deploy, backups, docs, history) to refresh the assistant's notes. Its main findings are in §6.

## 4. Decisions

- **Wix is the design source; this app is the product.** Assets were downloaded from the public site only. The Wix account, its settings, CMS and form submissions were not touched, and the domain still resolves to Wix.
- **Public pages get their own fixed palette and fonts.** The portal, the staff dashboard and the auth pages keep the Playfair + Inter token theme with light/dark. As a result there is no theme toggle before login. The pre-deploy review flagged this as a minor finding and it was accepted.
- **Fast-forwarded the branch onto main before committing** (main was one docs commit ahead with SES-2026-015). The main checkout's uncommitted firewall work and Tuqa renames were **not** merged in; they stay on `~/mydesign` awaiting their own decision.

## 5. Verification

- `tsc --noEmit` clean; eslint on the v5 files clean; `next build` passes (25 routes).
- A pre-deploy adversarial review ran as three independent reviewers covering shared-layout regressions, `/book` parity and the public pages. It found **no blockers or majors**. It checked:
  - All 50 asset paths exist with exact case (Vercel is case-sensitive).
  - Anchors match section ids.
  - The hero video has `muted` + `playsInline`.
  - There are no localhost URLs.
  - The portal button's localStorage keys match what `/auth/login` writes.
- One minor finding was fixed before commit: `SiteHeader` now wraps its localStorage read in try/catch, so a browser that blocks site data sees the logged-out button instead of a crashed page.
- Deployment was verified through the Vercel deployment API (state + commit SHA), not by curl-polling production (see SES-2026-015 on the Security Checkpoint incident).

## 6. Recall sweep findings (2026-09-30)

- **Production now holds real client data:** 8 staff, 4 clients, 4 projects.
  - RLS is off on 11 of 12 tables, and `admins` is anon read+write.
  - All 12 accounts share one plaintext password.
  - The storage buckets are public and anon-writable.
  - Security Phase 1/2 has not started, and it is now the top risk.
- **Nightly backup (BUG-016) is intermittent, not fixed.** Every run from 08-21 to 09-25 failed. The 09-26/27/28 runs were complete, and the 09-29 and 09-30 runs failed again. `project_notes` is missing from the table list, and storage is not backed up.
- **CI has failed on all runs since 2026-06-29** because the repo has no Actions secrets.
- **Realtime is published for only 4 of the 11 tables the app subscribes to.**
- **"Re-request pricing" writes NULL into NOT NULL columns.** It is still unlogged (candidate BUG-018), and one real pending `internal_quotes` row can now hit it.
- **The HDD mirror is manual and was behind.** The site-ready Wix assets were copied to the HDD this session and md5-verified.
