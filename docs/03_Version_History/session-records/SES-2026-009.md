## 2. Versions shipped

**v4.6.1 · Fix broken file uploads (files-table RLS restore)**
- What: The admin **Upload Files** page (and every file list — client Files page, project detail Files, admin recently-uploaded) had stopped working during testing: files uploaded to the storage bucket but "vanished," with no error shown. Root cause: `public.files` had **Row-Level Security enabled with zero policies** (deny-all), applied out-of-band directly in the Supabase dashboard — in no migration, while every sibling data table runs RLS-off. So the anon-key `insert`/`select` on `public.files` were rejected. Re-disabled RLS to restore parity (migration **0007**), and hardened `app/admin/uploads/page.tsx` so any storage/insert error is captured and shown instead of the old `if (!error)` swallow.
- Why: the report "we can't upload any files" — the feature was fully broken for testers and the silent-failure code hid why.
- Schema: `alter table public.files disable row level security;` (migration `0007_files_rls_restore.sql`). No table/column change.
- Decision: **PATCH** — a revert of an accidental change back to the documented baseline (ADR-0002). Recorded as a tracked migration so live-DB drift stops going unrecorded, and surfaced upload errors (BUGLOG BUG-010) so this class can't recur.

## 3. Schema changes

- **0007 `files_rls_restore`** (v4.6.1) — `alter table public.files disable row level security;`. Restores `public.files` to the same RLS-off posture as every other data table. Idempotent. This *records* a revert of an out-of-band manual change; it is not new design. Verified post-change: `files.relrowsecurity = false`, and the `anon` role can `insert`+`select` again (rolled-back probe row, left no data).

## 4. Architectural decisions

- **Live-DB schema changes must be captured as a tracked migration** — the files-RLS breakage was invisible precisely because it lived only in the dashboard, never in `supabase/migrations/`. Reinforces the standing ADR-0009 debt (no committed baseline); every schema/RLS change from here goes in a migration file first. Generating `0000_baseline.sql` remains open.
- **`public.files` stays consistent with its siblings (RLS off) until Security Phase 2** — Phase 2 will enable RLS + real per-row policies on *all* tables together; a lone half-done RLS-on `files` (what broke it) diverges from that plan and is reverted, not patched with a bespoke policy.
