## 1. Summary

A run of team-testing fixes and operator UX, ending in a large light/dark expansion. Fixed a **login regression** (a leftover client session trapped the owner out of the admin login — v4.8.1) and **staff management** (the `admins` table had no write policy — v4.8.2, DB-level). Then, per new requests: added a per-project **Upload Files tab** in the Project Hub (with a **"Sent <date, time>"** stamp per file), extended **light/dark to the entire designer/admin dashboard** with a clearly-labeled sidebar button, raised the **dark-mode contrast** floor, and made date pickers theme-aware (all v4.9.0). The theme work was built on a branch with an owner-reviewed Vercel preview before merge. A UI/UX pass (contrast, tap targets, labeled control, empty states) was applied using the interface-design priority rules.

## 2. Versions shipped

**v4.8.1 · Fix: owner login trapped by a leftover client session (BUG-013)**
- What: the v4.7.0 login convenience `router.replace()`d anyone with an existing `localStorage` session away from the form, so a stale *client* session bounced the owner to `/dashboard` and the owner login was unreachable. Replaced the forced redirect with a non-blocking "already signed in — Continue / or switch account" banner (form stays usable), and added `clearSession()` so a fresh sign-in wipes any other-role keys first (no coexisting client+admin sessions).
- Why: owner reported "the sign-in won't log me into the owner dashboard."
- Schema: none.
- Decision: PATCH — UX fix, not an auth-model change. (`app/auth/login/page.tsx`.)

**v4.8.2 · Fix: staff management blocked by admins RLS (BUG-014)**
- What: `admins` had RLS on with only a SELECT policy, so the Staff & Permissions page failed to add/edit/delete staff ("new row violates row-level security policy for table admins"). Added anon INSERT/UPDATE/DELETE policies (migration `0009`), applied to prod and verified (anon insert succeeds, rolled-back probe).
- Why: owner hit the error creating a staff account.
- Schema: migration `0009_admins_write_policies.sql`.
- Decision: PATCH — owner chose the quick self-service unblock. **Escalated security debt** (public key can now write the credentials table) — recorded in SECURITY.md finding #3; Phase 2 must move staff management server-side + hash passwords + revoke anon on `admins`.

**v4.9.0 · Upload Files tab + light/dark for the designer (admin) dashboard**
- What: (1) **Upload Files tab** in the Project Hub — per-project, shared to that client's portal, drag/drop, error surfacing, file count, empty state, ~44px tap targets, and **"Sent <date, time>"** under each file (from `files.created_at`). (2) **Light/dark across the whole admin panel** — migrated `app/admin/**` + `AdminSidebar` to the shared semantic tokens; a labeled **"Light mode / Dark mode"** button in the admin sidebar; **raised the dark muted ladder** (muted-1 .82 / -2 .60 / -3 .46 / -4 .34) for accessible contrast on every dark surface; date/time pickers follow the theme via `color-scheme`.
- Why: testers wanted to send files from within a project and see when each was sent; and light/dark in the designer dashboard.
- Schema: none (theming + an existing `created_at` column).
- Decision: MINOR — batch of operator UX, built on a branch with an owner-reviewed Vercel preview. The admin is one `/admin` surface for all roles, so "designer dashboard" = the whole admin panel.

## 3. Schema changes

- **0009 `admins_write_policies`** (v4.8.2) — anon INSERT/UPDATE/DELETE policies on `public.admins`. Verified live before commit. No table/column change. v4.8.1 and v4.9.0 shipped no schema changes.

## 4. Architectural decisions

- **Never force-redirect off the login form based on a stored session** — it traps role-switchers; offer a shortcut instead, and clear conflicting sessions on sign-in. (v4.8.1.)
- **`admins` opened to anon writes for now** to enable self-service staff management on the pre-launch build; a deliberate, documented security regression to be reverted in Phase 2. (v4.8.2.)
- **One theme system for all three surfaces** — admin now uses the same semantic tokens as marketing + client portal; the dark ladder was raised globally, so the contrast fix and the admin light/dark are the same change. Photographic overlays and the homepage-over-hero navbar stay literal in both themes. (v4.9.0.)
- **"Designer dashboard" == the whole admin panel** — `/admin` is one role-gated surface; theming covers every page.
